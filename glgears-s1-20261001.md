# S1: glgears on Mesa softpipe in the guest (2026-10-01)

S1 adds the software-GL baseline for the three-way gears benchmark: softpipe
vs OpenGL on Zink on the guest ICD vs native Vulkan gears. A glxgears-style
app (`glgears`) runs in the wasm32 Linux guest. It renders with Mesa 26.2.3
through surfaceless EGL plus desktop GL and presents each frame with
`glReadPixels` -> `XPutImage`. Softpipe works: at 300x300 it runs at about
88 FPS presented and about 187 FPS without presentation. Zink links into the
same binary and gets as far as `eglCreateContext`, where it fails with
`EGL_BAD_ALLOC`. The cause is the guest ICD rejecting a `vkCreateBuffer`
call; packet B2f covers that.

## What was built

- `web/linux/tests/glgears/glgears.c` ports glxgears (three fixed-function
  gears, display lists, lighting and depth).
  It uses surfaceless EGL, `EGL_OPENGL_API` and an FBO with RGBA8 colour and
  a 24-bit depth renderbuffer, and loads every GL entry point with
  `eglGetProcAddress`. Each frame is read back and presented with `XPutImage`
  into a 300x300 X11 window titled `glxgears` (direct BGRA copy when the visual
  allows it).
  - Options: `-nopresent`, `-seconds N`, `-size WxH`, `-info`, `-interval S`.
  - Output: glxgears-style `N frames in 5.0 seconds = X FPS` lines, plus
    `GLGEARS_FPS`, `GLGEARS_READY`, `GLGEARS_DONE ... avg_fps=` and
    `GLGEARS_ERROR` lines.
  - Exit codes: 0 ok, 2 EGL, 3 GL, 4 X11.
- `web/linux/tests/glgears/gputest-init` and `gputest-waiter` follow the G2
  pattern: rdinit adapter, waiter script, no subshells. The waiter reads the
  following from `/proc/cmdline` after X is up:
  - `gputest.gldriver=softpipe|zink`. Softpipe sets
    `LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=softpipe`. Zink sets
    `MESA_LOADER_DRIVER_OVERRIDE=zink LIBGL_ALWAYS_SOFTWARE=1`; the second
    variable selects the ICD's CPU device type.
  - `gputest.glmode=bench|present|nopresent`. `bench`, the default, runs
    30 s presented with `-info`, then 30 s `-nopresent`, then presented
    forever.
- `tools/glgears/build-glgears.sh TASKDIR BUILDNAME OUTNAME` statically links
  glgears with:
  - the Mesa softpipe+zink gallium archives and the EGL objects from a
    `tools/zink/configure-wasm32.sh ... -Dgallium-drivers=zink,softpipe`
    ninja tree. No Mesa source patches are applied.
  - the guest Vulkan ICD built with `-DGUEST_VK_ZINK=1`, plus its vsock
    transport.
  - `tools/zink/shims/zink_static_vk.c`, the mmap/unwind shims, and static
    Xlib/xcb/Xau.

  This packet adds an `ICD_SRC=DIR` override, so a link can use a
  `git archive` snapshot of the ICD instead of the live worktree, which other
  agents are editing. The binary imports only `env.memory`, `linux.syscall`,
  `linux.copy_siginfo` and `linux.get_thread_area`.
- `tools/guest-rootfs/package-gputest-glgears.py --wasm .../glgears.wasm`
  writes `web/linux/gpu/gputest-glgears.cpio` and its `.json`. The archive is
  newc, uncompressed, has no directory entries, uses 0:0 ownership and
  mtime 0, and is byte-reproducible.
- Page wiring is in `web/linux/gputest.mjs` and `web/linux/main.js`.
  - `?gputestapp=glgears` selects the archive. The allowlist is `cube` (the
    default, the G2 Vulkan cube) and `glgears`.
  - `&gldriver=` and `&glmode=` become the kernel arguments `gputest.app=`,
    `gputest.gldriver=` and `gputest.glmode=`. Only allowlisted values pass;
    anything else falls back to softpipe/bench.
  - Unit tests: `node --test web/linux/gputest.test.mjs` passes 7/7.

## How to run

```
web/linux/index.html?gputest=1&gputestapp=glgears                 # softpipe, bench
web/linux/index.html?gputest=1&gputestapp=glgears&gldriver=zink   # Zink on the guest ICD
...&glmode=present | &glmode=nopresent                            # single mode, no bench
```

## Zink status

- `gate-zink-run1` (package-run1, ICD snapshot = B2a `6742a69`): fails earlier
  than expected. The WebGPU session connects and Zink creates its screen with
  the "doesn't support base Zink requirements: logicOp scalarBlockLayout ...
  custom_border_color line_rasterization" warning. Then:
  `MESA-EGL: warning: DRI2: failed to create screen` and
  `GLGEARS_ERROR eglInitialize failed egl=0x3001`. The B2a ICD has no BGRA8
  configs; B2e added them.
- `gate-zink-run2` (package-run2, ICD from `git archive 2a26a22`, B2e):
  `eglInitialize` succeeds. Context creation fails with
  `MESA: error: ZINK: vkCreateBuffer failed` and
  `GLGEARS_ERROR eglCreateContext failed egl=0x3003 configs=1`
  (EGL_BAD_ALLOC). This is the known ICD rejection of Zink's buffer usage
  (B2f). The waiter retries 3 times and gives up, and the page stays healthy.

No Zink FPS yet. After B2f lands, relink with
`ICD_SRC=<git archive of the B2f commit> tools/glgears/build-glgears.sh
/mnt/p6/build/glgears-s1-20261001 s1 run3`, repackage and rerun
`&gldriver=zink`. The Mesa archives do not need rebuilding.

## Limitations

- The app is fixed-function GL 1.x through the compatibility profile. It
  measures single-threaded softpipe, not llvmpipe, which would need an LLVM
  JIT and is not possible in native wasm.
- The size is a fixed 300x300 (glxgears default). There is no vsync and no
  frame cap. Softpipe renders on one thread.
- Presentation is a CPU copy (`glReadPixels` + `XPutImage`), not GLX or EGL
  window surfaces. Absolute FPS depends on the host CPU and load. Each
  number is one run per package; results from run1 and run2 agree within
  about 3%.
- The Firefox mode (`&firefox=1`, which delays the start by 20 s) was not
  gated for glgears.

## 128x128 softpipe run (matched to vkgears V1)

The page now passes `&glsize=WxH` as `gputest.glsize=` to the waiter, which
adds `-size WxH` to every glgears phase. The CPIO was repackaged from the same
`link/run2/glgears.wasm` (`package-run3`, reproducible, 20,473,344 B, sha256
`997e8c30bc15f61b76c859567764aaa4eb8824f54ca6a164573f290e47994f10`).

Gate `/mnt/p6/build/glgears-s1-20261001/gate-softpipe128-run1`
(`?gputest=1&gputestapp=glgears&gldriver=softpipe&glsize=128x128`, NVIDIA
recipe, B2f gate running concurrently on the host): pass.

| Phase | FPS mean (min-max) |
|---|---|
| present (128x128 window) | 202.3 (176.5-210.5) |
| nopresent (glFinish) | 451.6 (446.0-457.1) |

At the same render size, softpipe is faster than vkgears on the guest ICD
(NVIDIA WebGPU 59 present / 189 nopresent, `docs/vkgears-v1-20261001.md`).
Gears are cheap to rasterise. The ICD's fixed per-frame cost dominates: a vsock
round trip per submit, all buffers re-uploaded each frame, and waiting for
host completion. vkgears also upscales to a 300x300 window when presenting.
